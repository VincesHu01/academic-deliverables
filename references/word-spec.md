# Word 规格基线

以下规则适用于课程作业、研究报告、文献综述、讲座笔记等常见 Word 交付物；用户提供模板时以模板为准。

## 一、字体

| 用途 | 字体 | 字号 |
| --- | --- | --- |
| 正文 | 宋体 | 小四（12pt） |
| 一级标题 | 黑体 | 三号（16pt） |
| 二级标题 | 黑体 | 四号（14pt） |
| 三级标题 | 黑体 | 小四（12pt） |
| 说明性文字 / 图注表注 | 楷体 | 五号（10.5pt） |
| 公式 | Times New Roman | 与正文同号，**斜体** |
| 代码 / 原始输出 | Consolas 或等宽 | 五号 |

> 默认仅使用宋体正文、黑体标题、楷体说明、Times New Roman 斜体公式和等宽代码字体。

## 二、版面

- **行间距：1.5 倍**（统一，不例外）
- **颜色：正文默认只使用黑色**；仅在模板或任务明确要求时使用其他颜色
- 表格 / 图片背景一律白色
- 图片内容颜色只允许：黑、红、蓝、灰
- **不要页眉、页脚、页码、任何格式化标记**
- 中英文符号统一（全角/半角、破折号、引号）
- 小数点位数全文统一（如统一 3 位或 4 位）
- 图注表注格式统一："图 1 ……" / "表 1 ……"，图在上注在下，表在上注在上

## 三、公式：必须用 OMML 对象

数学符号和公式应使用 Equation / OMML 公式对象呈现，避免用普通文本模拟复杂公式。

即：`<m:oMath>` 节点，不是纯文本。手工写 docx 时可用 `docx.omml` 或直接注入 OOXML。
`check_docx.py` 会扫描疑似公式文本（含 `^`、`_`、`\sqrt`、`β`、`∑` 等）却不在 `m:oMath` 中的段落并告警。

## 四、表格：学术三线表

- 默认用三线表（顶线、表头下线、底线），无竖线、无内部横线
- 数字右对齐，文字左对齐
- 表头用黑体小四，表体宋体小四
- 单位标注在表头括号内，不要在单元格里重复
- 结果类内容优先使用结构化表格呈现，不要散落成无关联段落

## 五、结构模板

### 课程作业类
```
题目 + 数据解读 + 代码 + 原始输出 + 结果分析 + 社会经济意义解读
```
可按任务删减或调整，但要保持题目、方法、输出与解释之间的对应关系。

### 研究报告 / 蓝皮书类
```
引言 → 研究方法 → 分章节数据分析 → 案例或主题分述 → 结论与建议
```
- 用户提供参考终稿或模板时，严格参照其语言风格与格式，不自创体例
- 数据更新时同步更新文献：需补 3–4 篇真实 CSSCI/SSCI，改动的文内引用**要高亮标出**

### 文献综述类
```
问题提出与研究演进 → 分主题章节 → 总体评价与研究展望
```
- 每章之间必须有过渡句，末尾要有收束
- 引用格式：作者（年代），精确到人名和年份
- 章节标题要具体，禁止"一、二、三、四"式抽象标题

### 讲座笔记 / 会议纪要类
- 内容应有条理、具备学术逻辑和思辨性
- 明确区分事实记录、发言摘要与撰写者判断
- 可保留适量自然口语，避免模板化和过度正式

## 六、代码与产物规范（课程作业场景）

- 代码必须有**标准化注释**，尤其体现逻辑推理的部分。禁止"一长串代码一个注释都没有"
- 代码必须可直接运行，并说明必要的依赖、输入和运行顺序
- 产物输出目录规范、命名规范：`题号 + 原始输出`（多个则 `题号+原始输出+序号`）
- 截图类产物：不截取软件标识栏和时间戳
- **同一个题的原始输出与图表禁止跨页**，必须同页呈现
- 源码汇总成单一文件（如 .do），保存到指定目录，再三核验无报错

## 七、排版密度

可用**无框表格**把同一题的各部分（题目 / 输出 / 分析）框在一起，视觉上成组，避免长条散乱与过度分页。

## 八、字数

用户给出精确字数时：
- 给的是"左右" → 控制在 ±10%
- 给的是精确上限（如"不得超过 660 字"）→ 卡死，宁少勿多
- 默认宁短勿长；若用户明确要求详细，再增加必要展开
